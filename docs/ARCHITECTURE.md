# Устройство Casement

Всё написано на Rust. Сеть и протокол — свои, интерфейс — GTK 4 и Libadwaita через
`gtk4-rs` и `libadwaita-rs`, видео и звук — GStreamer. Один и тот же код работает на
Linux и Windows.

```
┌──────── клиент (управляет) ────────┐        ┌────────── хост (управляемый) ──────────┐
│ casement — GTK 4 + Libadwaita      │        │ casement-host — служба сеанса          │
│   компьютеры, сеанс, настройки     │  QUIC  │   захват экрана, кодирование H.264     │
│   GStreamer: декодирование, звук   │◄──────►│   ввод, буфер обмена, файлы, звук      │
│ casement-net — сеть, вход, поиск   │  UDP   │ casement-net + casement-media          │
└────────────────────────────────────┘        └────────────────────────────────────────┘
```

## Крейты

| Крейт | Что внутри |
|---|---|
| `casement-proto` | сообщения протокола (protobuf через `prost`, схема в коде), версия, ограничения размеров |
| `casement-net` | QUIC (`quinn` + `rustls`), ключи устройств, вход OPAQUE, доверенные устройства, mDNS, сеанс хоста и клиента, файлы, датаграммы звука |
| `casement-media` | хост: экран, ввод, буфер обмена и звук на GNOME (Mutter D-Bus, PipeWire) и Windows (Desktop Duplication, `SendInput`, Win32 clipboard, WASAPI) |
| `casement-app` | приложение `casement`: страницы навигации, сеанс, вывод видео через `gst-plugin-gtk4` |
| `casement-host` | служба `casement-host`: принимает подключения без открытого окна |
| `casement-cli` | `casement-cli`: пароль, приём подключений, подключение с записью экрана, замеры, поиск |

Сеть живёт в Tokio, интерфейс — в главном цикле GTK; между ними каналы `async-channel`.

## Сеть и вход

- **Транспорт** — QUIC поверх UDP, порт 47820. Поток управления, отдельный поток
  видео, поток на каждый файл, отдельный надёжный поток нажатий и прокрутки;
  движения указателя и звук идут датаграммами.
- **Ключи.** У каждого устройства свой ключ Ed25519 и самоподписанный сертификат;
  отпечаток — SHA-256 открытого ключа. TLS 1.3 взаимный, ALPN `casement/1`.
- **Первое подключение.** Клиент запоминает ключ хоста без вопросов. Если ключ
  знакомого компьютера изменился, подключение останавливается до решения человека.
- **Пароль доступа** — OPAQUE (Ristretto255, Argon2id), контекст — экспортёр TLS этого
  соединения. Пароль не передаётся; хост хранит запись, по которой войти нельзя.
  Неудачные попытки замедляются: три бесплатные, дальше пауза удваивается до 5 минут.
- **Доверенные устройства.** После входа по паролю хост запоминает ключ клиента, и
  дальше тот входит без пароля, пока его не уберут.
- **Настройки хоста** (пароль, доверенные) перечитываются перед каждым входом, поэтому
  изменения из приложения или `casement-cli` действуют сразу, без перезапуска службы.
- **Служба `casement-host`** принимает подключения без окна и включена по умолчанию: на
  Linux — пользовательская служба systemd (пакеты включают её для всех,
  `systemctl --global`), на Windows — системная служба «Casement». Её включают и
  выключают «Принимать подключения», `casement-cli accept` и мастер `casement-cli setup`.
- **Служба Windows** работает от SYSTEM с запуска Windows, до входа в систему. Сама она
  живёт в сеансе 0 без рабочего стола, поэтому запускает рабочий процесс
  (`casement-host --worker`) в сеансе консоли на рабочем столе, который сейчас получает
  ввод: `Default`, `Winlogon` (экран входа, блокировки, окна UAC) или `Screen-saver`.
  Процесс захватывает и управляет только своим рабочим столом; когда ввод переходит на
  другой, он завершается с кодом этого стола, служба запускает его там же, а клиент
  переподключается. Настройки машины (ключ, пароль, доверенные) лежат в
  `%ProgramData%\Casement` с доступом только для SYSTEM и администраторов; для
  приложения служба публикует сводку в `public\status`, а меняются настройки мастером
  `casement-cli setup`, который приложение запускает с запросом UAC. Файлы — в общих
  папках `C:\Users\Public`.
- **Источники.** По умолчанию хост принимает только частные адреса, CGNAT 100.64/10
  (Tailscale), ULA и loopback.
- **Поиск** — mDNS `_casement._udp.local.` с записями `v`, `name`, `os`, `fp`.

## Экран и ввод

- **GNOME.** Сеанс Mutter `RemoteDesktop` + `ScreenCast` (без диалога портала):
  `RecordMonitor` выбранного монитора или `RecordVirtual` для экрана под размер окна
  клиента. Кадры из PipeWire идут в `vapostproc ! vah264enc` (запасные — `openh264enc`,
  `x264enc`). Ввод — методы того же сеанса Mutter.
- **Windows.** `d3d11screencapturesrc` выбранного монитора и первый работающий
  кодировщик из `amfh264enc`, `qsvh264enc`, `nvd3d11h264enc`, `mfh264enc`. Ввод —
  `SendInput`: абсолютные координаты по виртуальному рабочему столу, коды evdev
  переводятся в скан-коды set 1.
- **Доставка ввода.** Клавиши, кнопки мыши и прокрутка идут последовательно по
  надёжному потоку с приоритетом выше видео. Очередь ограничена: при переполнении
  соединение закрывается, хост отпускает все удерживаемые клавиши и кнопки.
  Движения имеют порядковый номер; устаревшие координаты отбрасываются. Клик
  сохраняет свою позицию, даже если его обогнало более новое движение. Возможность
  согласуется полем `reliable_input` в `ServerHello`; версия протокола остаётся 1,
  со старыми узлами сохраняется прежний ввод датаграммами.
- **Клавиатура клиента.** Linux передаёт аппаратный код GDK минус 8. На Windows
  код GDK — виртуальная клавиша Win32: клиент получает физический скан-код через
  `MapVirtualKeyExW` с текущей раскладкой, затем переводит его в evdev. Цифровой
  блок и правые модификаторы различаются отдельно.
- **Клиент.** `appsrc ! h264parse ! vah264dec ! vapostproc` в `gtk4paintablesink`,
  встроенный в приложение. На Windows — `d3d11h264dec ! d3d11convert`: видеокарта
  переводит цвета и сразу подгоняет кадр под размер окна, потому что интерфейс там
  рисует Cairo (GL и Vulkan в GTK 4.21 закрашивают тень окна чёрным, GTK issue 7567),
  и ему остаётся только скопировать кадр. Когда сеть не успевает, хост пропускает
  кадры до следующего ключевого.

## Звук, буфер, файлы

- **Звук.** Монитор вывода по умолчанию (на Linux через API PulseAudio, на Windows —
  WASAPI loopback), Opus 48 кГц по 20 мс. На Windows Opus кодирует и декодирует
  libopus напрямую, так как в GStreamer для mingw нет плагина Opus.
- **Буфер обмена** — текст в обе стороны: через Mutter на GNOME, через Win32 на
  Windows.
- **Файлы.** Отправленные на хост попадают в «Загрузки»; хост показывает свою
  домашнюю папку и отдаёт из неё файлы. Пути за её пределами, в том числе через
  ссылки, отклоняются. Файл пишется во временный и переименовывается только после
  сверки размера и SHA-256, существующие файлы не перезаписываются. Отсутствие
  прогресса 30 секунд завершает операцию; общая длительность передачи не ограничена.

## Настройки

`~/.config/casement` на Linux, `%APPDATA%\casement` на Windows (у службы Windows —
`%ProgramData%\Casement`) или `$CASEMENT_CONFIG_DIR`; файлы с правами 0600:
`device.key`, `connections.ini`, `host-password`, `trusted-devices`.
Запись идёт через отдельный эксклюзивный временный файл. Создание ключа не заменяет
уже созданный ключ: одновременно запущенные процессы перечитывают ключ победителя.
